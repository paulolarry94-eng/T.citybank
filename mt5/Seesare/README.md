# SEESARE router: Phase 1 modules (clock and cycle ledger)

**Status: uncompiled source.** MQL5 cannot be compiled in the build container. Every rule is mirrored in a Python twin
(`tools/seesare_verify.py`) that is tested here (`research/truth/tests/test_seesare_phase1.py`, 32 tests). The MQL5 self-test
script carries vectors generated by that twin, so one run in MetaEditor/MT5 shows whether the compiled code agrees.

## Install and run the self-test

1. Copy `Include/Seesare` to `<MT5 data folder>\MQL5\Include\Seesare` and `Scripts/SeesarePhase1SelfTest.mq5` to `MQL5\Scripts`.
2. Open the script in MetaEditor and compile (F7). Send me any compiler message verbatim.
3. Drag the script onto any chart. Inputs: the server scheme you intend to declare (`GMT2_EU`, `GMT2_US`, ...), whether to run the
   360-event lifecycle (about 800 small files, a few seconds), whether to keep the test files.
4. Read the Experts tab: `PASS`/`FAIL` lines, then `N passed, M failed`. Any `FAIL` shows what it got and what it expected.
   `INFO` lines report the measured server offset, which schemes match it today, today's windows in UTC and server time, and the
   spread gate's verdict on the chart symbol.

The broker's DST rule (EU dates or US dates) can only be told apart between the 2nd and the last Sunday of March and in the week
after the last Sunday of October; the script says so when it cannot tell.

## How the router will use it (Phase 2)

```
OnInit:  clock.Init(scheme); matrix.LoadDefaults(); ledger.Open("seesare\\<login>", "<lifecycle id>", clock.UtcNow());
OnTimer: clock.Tick(); ledger.Retry();
Before an entry (window w):
         plan  = ledger.PlanUsdAt(ratio, domain)          planned delta on the $1,000 baseline at the current level
         risk  = loss at the stop for the rounded-DOWN volume + commission + swap and slippage allowances
         REAL only if: volume >= broker minimum AND ledger.AllowsRealRisk(risk) AND gate.Check(...) == PASS
         otherwise the event runs as SHADOW (paper) and still moves the ladder
After the exit:
         e.resolution = CSeesareLadder::Classify(e.close_by, e.delta_usd, policy); ledger.Record(e, hash)
```

Files live in the terminals' common folder, `Common\Files\seesare\<login>\<lifecycle>\`: `ledger.txt` (one line per event),
`anchors.txt` (one line per closed cycle), `state.dat` (+ `.bak`), `outbox\NNNNNNNNNN.msg` (+ `outbox\sent\`).

Anyone can check a lifecycle: `python3 tools/seesare_verify.py ledger.txt anchors.txt` (exit 0 = intact, 1 = broken,
3 = intact but the envelope rule was broken).

## Rules the code enforces

- **Ladder (SEESARE 7.1):** positive outcome +1 level; 1st/2nd/3rd+ negative in a row -2/-3/-4; manual resolution changes
  nothing and keeps the negative run. The ledger computes the levels itself; a caller cannot write a different level.
- **Multiplier:** ratio >= 3.5: min(1 + 0.10 (r - 3.5), 1.5); below: max((r / 3.5)^2.0, 0.082) (owner's exponent 2.0).
  Multiplier and planned delta are rounded **down** to 4 decimals, so MQL5 and Python write identical text (SEESARE's own
  values at levels 9, 13 and 15 fall exactly on a rounding tie, e.g. $0.03135).
- **Cycles:** 10 REAL events per cycle, 36 cycles, lock at 360. SHADOW events move the ladder but carry no money and do not
  count toward the 10 or the 360. They are written to disk, not kept only in memory: a VPS restart must not lose the ladder.
- **Envelope guard:** a REAL event may open only if the lifecycle's drawdown + its all-in risk <= $36 (3.6% of $1,000).
  This, not the ladder, is what holds the 3.6% line (see below). It covers planned losses; a price gap through the stop can
  still exceed it. Once the room left is smaller than one event's risk, real trading stops for that lifecycle and does not
  restart by itself: continuing means a new lifecycle id, which is the owner's decision.
- **Keyless chain:** every line carries the previous line's hash. Anyone can recompute a keyless chain, so it proves integrity
  against heads published elsewhere (the outbox stream, `anchors.txt`, a public post), and each REAL line carries the broker
  deal tickets for matching against the statement.
- **Restart:** `Open` replays `ledger.txt` through the same code that wrote it, refuses a ledger shorter than `state.dat` says
  (lost lines), a ledger that differs from the saved head, or an `anchors.txt` that disagrees, then re-sends any outbox
  message not yet written. Delivery is at least once; the relay drops duplicates by (life, kind, ref).

## Why the envelope guard was added (correction of an earlier claim)

The blueprint said that counting time exits as manual resolutions holds the SEESARE envelope (0.25% in one pattern). That was
incomplete. Recomputed over 360 events with the twin:

| Pattern | Ladder rules only | With the envelope guard |
|---|---|---|
| Every event exits on time at -0.6R, time exits = MANUAL (the mandate) | 29.55% drawdown | 3.53%; real trading stops after 43 events |
| Same, but a losing time exit counts as NEGATIVE | 0.19% | 0.19%; all 360 real |
| Stop at 3.5:1, then two target hits at 1:1, repeated | 14.96% | 3.60%; real trading stops after 160 events |

The time-exit policy is an input (`ENUM_SEESARE_TIME_POLICY`); the default follows the owner's mandate (`SEESARE_TIME_EXIT_MANUAL`).
